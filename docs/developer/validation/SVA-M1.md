# Validation Pack: SVA-M1, the mapping schemes listed on the left

**Unit:** `studio-visual-authoring`, slice SVA-M1 of the [plan](../plans/studio-visual-authoring.md), from section 10.1 of the [sketch](../sketches/studio-visual-authoring.md), built on 2026-11-12 in autonomous mode.

## Invariant

Every mapping scheme of the workspace is visible and selectable at once in mapping mode's left column, and each row's summary is derived from the mapping part's graph and the last sample run, and never stored. The `Mapping scheme` select is gone.

## What changed

- **The summary.** `schemeSummary` in `rdf/mapping.ts` counts a scheme's mappings, the mappings another mapping names as its template, each reviewed mapping by its latest decision, and the mappings a proposal generated that no review has decided. It reads the `Scheme` that `schemesOf` returns and holds no state.
- **The list.** `SchemeList` in `ui/MappingView.tsx` takes groups of `{ title, schemes }` and renders one group, "Schemes", as a `nav` named "Mapping schemes". Each row is a button with the scheme's label, its compact IRI, its counts, its review state and, once a sample has run, the triples the run wrote for its mappings. The current row carries `aria-current="true"`. A row selects the scheme, clears the selected source concept and goes to mapping mode with no mapping picked, as the select did.
- **The fake service.** `e2e/fake-service.ts` gains the `mapping` part in the parts a new workspace holds, so a workspace made from a mapping sample can be created in a browser test.

## Deliberate non-coverage

- Template libraries in the list are SVA-M2d. `SchemeList` takes groups so that slice adds one.
- The sample pane and when a sample runs are SVA-M3b. This slice changes neither.
- The count of triples written is read from the last run through the existing `sampleRun.output`, and no test asserts it, since it needs a run the fake service does not serve.
