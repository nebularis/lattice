# Validation Pack: Ledger LG-19, the benchmark's corpora refuse a debit beyond availability

**Unit:** `ledger` ([plan](../plans/ledger.md), [status](../status/ledger.md)). **Builds on:** LG-18 ([its pack](LG-18.md)) and LG-14 to LG-17 through it. **Decisions:** LG-Q23, LG-Q26, ADR-A124. **Brief:** [the cloud brief of 2026-11-13](../notes/cloud-brief-lg-19-2026-11-13.md).

## Invariant

No account on the benchmark's account tree stands below zero at any posting of a stream the benchmark generates, since a debit more than the stepwise balance of any account on its path is refused as the writers refuse it and is not a posting. Where no debit is refused the stream is the one the benchmark generated before, posting for posting. A refused debit leaves no trace in the stream, the model's rows or the stored count, and a stream of `count` postings has `count` postings at positions without a gap.

The Jena test kit has to be built first (`mise run bootstrap:sparql-testkit`), or two Jena tests skip. The first command is 151 and 22 tests. ## Artefacts

`benchmark/ledger-credit-kinds/check.py` (`refuses_debit`, `generate`, `stream` and `stream_two_level`), `writes.py` (`Live.prepare` uses `refuses_debit`), `test_check.py`, and the two benchmark READMEs, each with a dated passage "Measured again on corpora that refuse an overdrawing debit (LG-19)".

## Deliberate non-coverage

The tree's stated amounts, the seed, the debit and credit sizes and the shares, which are the maintainer's to change. The sketch's four-step tree and the fixed interleavings, which do not use the streams. The write benchmark's request lists, which are drawn from the two-level stream and settled against a store, so the live writers still refuse some debits for lack of availability. A corpus that refuses debits and is drawn at a credit share so low that it cannot reach its count raises and is not repaired.
