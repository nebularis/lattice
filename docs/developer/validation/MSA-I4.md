## Scope

- The note [MSA-I4-four-operations-lowered.md](../notes/multi-store/MSA-I4-four-operations-lowered.md). A neutral IR of guarded commands written in the shape of an Isabelle datatype, four commands in it (a create, a delta replace under a patch log, an event append with the dataset guard, a key claim write), each construct lowered to SPARQL 1.1 Update, PostgreSQL and ISO GQL in form, and each resource's relational and property-graph counterpart.
- Out of scope. Mechanising the IR, which is MSA-I5. Any ledger operation. Running any SQL or GQL text.

## Result in one paragraph

The falsifier does not fire. No construct of the IR belongs to one dialect, and GQL's only extra need is a key constraint on a label, which the capability record would declare. Every resource has a relational counterpart, an aggregate whose shape is not closed falling back to a table of its facts. The exercise found that the SPARQL text leaves three choices implicit (the order of guards, whether the patch log holds requests or effects, and who advances the sequence on a replace) and that the contract's logical key for an event names the append and not the event.

## Adversarial probes

1. The note looked for a construct with no counterpart in one dialect. The candidates were the zero-padded revision IRI, set semantics of edges, an insert-if-absent and the reading of every value before any write. Each has a counterpart or a rule of the lowering, set out in the note's §4.
2. A resource with no counterpart was looked for among the eight the four commands touch. The aggregate without a closed shape was the nearest case, and a fact table holds it.
3. The SQL text of the delta replace was written out in full because it is the one where SQL's reading of its own writes could change the result, and the order of reads and writes in it was checked against the IR's rule.

## Decisions taken

- **The guards are ordered, with a resend first.** A request that was already applied answers `Duplicate` whatever else has changed since, which is what makes a resend change nothing.
- **The fallback for an open shape is a fact table.** It keeps every family placeable, at the cost of the benefit SQL would bring.
- **No GQL product was chosen.** The column is ISO GQL in form, each entry to be checked against the product.
