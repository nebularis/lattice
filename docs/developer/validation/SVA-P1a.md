# Validation Pack: SVA-P1a, the compiled profile states where a target's data lands

**Unit:** [`studio-visual-authoring`](../status/studio-visual-authoring.md), slice SVA-P1a, built on 2026-11-18 and 2026-11-19 in autonomous mode, from the [compiled landing places sketch](../sketches/compiled-landing-places.md) as the maintainer answered SVA-Q17 to SVA-Q23.

## Invariant

Every write access of a compiled profile lands in exactly one `dal:GraphPlace`, which states one `dal:GraphRole` and either a fixed graph or a template of the closed placeholders `{root}`, `{newRev}` and `{month}`. A read access lands nowhere. A place is stated once in a profile, with an IRI minted from the target as the profile's other declarations are, so the same compilation gives the same places. A patch log's added and removed triples are two accesses that differ by `dal:patchDirection`, the constant part of `PatchContent`'s logical key. The logical resource kinds are unchanged. A graph the compiler cannot state as a place is refused, naming the operation and the graph term, and no placeholder is invented.

## What changed

- `tools/persistence/src/persistence/landing.py` is new. It reads each write graph from the operation's own typed IR, from the term of each graph block and the `Bind` of each variable it names, and states it as a `Place`. The studio worker's derivation of SVA-P1 was the starting point. The worker itself is unchanged until SVA-P1b.
- `contract.py`: `AccessContract` gains `place` and `direction`, both optional, and a total order over accesses. `contract_emit.py` mints and emits each place once, links write accesses by `dal:landsIn`, and states `dal:patchDirection` and `dal:forConstraint`. `compiler.py` and `model.py` compute the matched scopes and the scope each value won through at compile time and emit `dal:matchedScope` and `dal:wonThrough`. `ir_render._term_text` became the public `term_text`.
- `ontology/persistence`: the vocabulary, the README's sections on the operation contract with its class diagram, and a release note under Unreleased. The shapes gain the write access's one place, a read access's none, the direction on a patch access only, `GraphPlaceShape` with the closed role set and placeholders, and `ResolvedDimensionShape`, whose `dal:wonThrough` must name a scope the same profile states as matched.
- 15 expected profiles and 8 compiled profiles of the Python caller library regenerated by `tools/persistence/tests/expected_profiles.py`. `baseline-single-class` goes from 50 accesses to 52, the patch log's one access becoming two, with 7 places and 30 `dal:landsIn` links.
