With the tasks over `vyd`, INDEX.md regenerated byte for byte. ROADMAP.md regenerated with three of those cells in its branches table, one sentence of the generated text in section 9.2, which now reads "a sketch, a plan or a decision", and the changes this record's own move to building makes, a chart of its own in the gantt and the counts in the glance and branches tables.

After the deletions, `mise run check:hooks` passed with 45, every work-board test running against `vyd`, `mise run check:knowledge` with 38 once CAP-103 and CAP-104 pointed at the files that replace the old ones, `mise run check:identifiers` at 2107 identifiers mentioned and 0 unresolved, `mise run check:catalogue` at 20 modules and 15 tool packages agreeing with the tree, and `mise run check:agent-guidance` with 9. The first commit of the slice was refused by its own `work` check: inside git's hook, where `GIT_DIR` is exported, `vyd work check --staged` crashed, since `git -C <status folder> rev-parse --show-toplevel` answers the folder itself under `GIT_DIR` and `vyd` took the status folder for the repository root. The same command passes from a shell, through `mise run`, and through `python tools/hooks.py run pre-commit`, and fails from a shell with `GIT_DIR` set, which is the reproduction given to Вивід's side. Вивід 0.2.7 fixes it where `vyd` starts, the workaround `tools/vyd.py` carried for a day is gone, and `test_vm4_01` holds the fix. `mise run check` ran after the slice, unfiltered to a file, exit 0 from `mise` in 194.10 s, and its 3,447 lines were compared line by line with the VM-3 log the agent had read whole, differing only in `check:hooks` at 46 passed, `check:identifiers` at 855 files, and timings.
