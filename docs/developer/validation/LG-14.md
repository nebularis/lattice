# Validation Pack: Ledger LG-14, the read cost of credit kinds

**Unit:** `ledger` ([plan](../plans/ledger.md), [status](../status/ledger.md)). **Decisions:** LG-Q10 decided 2026-11-10, LG-Q9 (a), ADR-A124, STD-155, STD-176. **Reads:** the [balances sketch](../sketches/ledger-balances-under-post-once.md) §3 and §4.5.

## Invariant

Before the credit kinds of LG-Q10 are built, their read cost is known on every engine the repository runs: an ancestor's balance under post-once with period graphs, read as the plain fold of today's design, as the fold that counts only the credits whose kind the ancestor accepts, and as the fold that applies the ancestor's ceiling posting by posting, each equal to a model's balance.

## Handoff

Built 2026-11-11 on machine R by a Sonnet subagent and checked here. The full run passed four times, the last of them reported, about 383 s. The quick run here, 2026-11-11: 24 tests passed in 15.3 s, then every read on rdflib 7.6.0, pyoxigraph 0.5.13 and Jena ARQ 5.1.0 equal to the model, exit 0.

Time of the 27 ancestor reads against the plain fold, 30% credits, for 1,000 / 5,000 / 20,000 postings:

| Backend | kind-filtered | stepwise |
|---|---|---|
| rdflib | 1.77 / 1.71 / 1.24 | 1.56 / 1.57 / 1.21 |
| Oxigraph | 1.69 / 1.70 / 1.69 | 1.90 / 1.97 / 1.95 |
| Jena | 1.18 / 1.34 / 1.35 | 3.43 / 4.49 / 4.89 |

Per root read at 20,000 postings, 30% credits, plain against kind-filtered against stepwise: rdflib 4,498 / 5,463 / 5,412 ms, Oxigraph 90.7 / 154.6 / 179.3 ms, Jena 138 / 190 / 754 ms. A kind adds one triple per credit. The README holds every size, the 5% rows and the sublimit and section reads.

**Findings.**

- The kind filter costs 1.2 to 1.8 times the plain fold on every engine, and the factor does not grow with the history.
- The stepwise fold costs about what the filtered fold costs on rdflib and Oxigraph. On Jena it costs 2.9 to 4.9 times and grows, which is the sort plus every row crossing the test kit's JSON pipe, a cost a native Jena caller would not pay, so it is a hypothesis for Jena TDB2 (STD-176).
- The form of the kind join is engine-specific, and the wrong form is a real cost: at 20,000 postings, `OPTIONAL` costs 4.1 times plain on Oxigraph against `UNION`'s 1.7, and `UNION` costs 6.0 times plain on rdflib against `OPTIONAL`'s 1.2. The benchmark uses the cheaper form per engine. Neither query plan was inspected.

**Deliberate non-coverage.** Checkpoints, so every read folds from the start of history. The ceiling clamp at a contract, which is applied at the ancestor only. Jena TDB2 and Fuseki, since Jena runs as the in-memory test kit. The stepwise loop timed apart from its sort and transfer. Whether a plain filtered sum with a check against the stated amount suffices where an ancestor's ceiling cannot bind, the shortcut the maintainer was told of, which is not measured.
