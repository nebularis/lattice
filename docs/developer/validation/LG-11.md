## Invariant

The ledger never converts. It declares no term for a conversion: no `ldg:conversionMethod` on an account definition, no `ldg:amountAsDrawn` or `ldg:conversionUsed` on a posting, and no `ldg:ConversionTogetherShape`. Every posting in an example is in its account's unit. A conversion made before the ledger is a record outside it, which a posting may cite by `prov:wasDerivedFrom`, as it cites a merge record.

## Deliberate non-coverage

- **No shape refuses a draw in another unit.** That is LG-12's, as the plan's row says, so a posting stating a euro amount is not yet refused by the ledger.
- **The conversion record has no term.** The example states it with `prov:Entity`, `prov:wasDerivedFrom` and a comment. Where a conversion is recorded, and with which terms, is Quantification's or the caller's, and is not decided here.
- **The release register** (`docs/architecture/ontology-releases.md`) is not edited, since no version moves on the branch.
- **The 0.18.0 release note** still names the conversion method, since it records what that release held.
