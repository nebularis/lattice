## Invariant

An account definition is a `fnd:Versioned` with one persistent identity. Its stated amount and its credit ceiling are quantities minted under its IRI, and its parent, its merge policy, its unit of account, its period recurrence and the edition of its credit kinds are versioned things it names by version. Every edge whose object is part of a definition's meaning is marked `fnd:meaningBearing`, so Foundation's `fnd:MeaningBearingEdgeShape` finds nothing on any example and warns where an edge leads to a node that is neither versioned, minted under its subject nor a published term. A definition that names the kinds that restore it pins, with `ldg:creditKindsEdition`, the one edition they were resolved against, and each kind it names is a concept of that edition.

### Each edge, marked or not, and why

| Edge | Marked | Why, by ADR-A142 decision 1: would an edit of what it leads to change what a past version meant |
|---|---|---|
| `ldg:statedAmount` | yes | every balance is the stated amount less what was drawn. An edit of a shared quantity would move every past balance |
| `ldg:creditCeiling` | yes | every credit is applied up to it |
| `ldg:partOf` | yes | the parent's amount, ceiling and kinds bound every draw and credit on the child |
| `ldg:mergePolicy` | yes, already | every merge is settled under it |
| `ldg:restoredBy` | yes | which credits restore the account. A kind's meaning is fixed by the edition the definition pins |
| `ldg:creditKindsEdition` | yes | the edition is what fixes the kinds' meaning for a historical read (LG-Q22) |
| `ldg:unitOfAccount` | yes | the value space says what an amount is, its additivity, units and operations. `qnt:ValueSpace` is a `fnd:Versioned`, so the edge names a version |
| `ldg:periodRecurrence` | yes | its bins say which account a draw was on. `qnt:Recurrence` is a `fnd:Versioned` |
| `ldg:residualAccount` | yes | LG-26's pack asked. What becomes of a residual is part of the treatment the policy states (LG-Q41), and the account it goes to, with its own amount, ceiling and policy, is part of that. So a policy version names a version of the definition, and a later version of the definition reaches the policy only through a new version of the policy |
| `ldg:admitsOwnerKind` | no | the object is a class, which the ontology that declares it versions by its release (ADR-A146), and the ledger reads only an owner's type |
| `ldg:countsPurpose`, `ldg:keyDimension` | no | a purpose and a key are concepts a record names and the ledger compares by IRI, as it compares a credit kind. Whether their schemes' editions are pinned as the credit kinds' is is not decided, so it is a question below and an issue in section 13 |
| `ldg:resetRecurrence` | no | deprecated, and removed by LG-3 |
| `ldg:closingRecurrence` | no | on the profile, which `ldg:ledgerProfile` already pins. It tunes cost and changes no meaning (LG-Q24) |

### Choices this slice made

- **The pin is `ldg:creditKindsEdition`, an edge to a scheme edition.** ADR-A131's first addendum of 2026-11-16 says Ledger declares the kinds' contract and an applied module binds it, and LG-25 declared `ldg:CreditKinds` as a scheme with no member. A pin to `ldg:CreditKinds` itself would pin nothing, since the scheme does not change, and Vocabulary's `voc:resolvedUnder` names a binding, not an edition, and would need a scheme contract the ledger does not declare. So the definition names the edition, a version of the scheme an applied module publishes its kinds in, and a kind is a concept of both that edition and `ldg:CreditKinds`. The range is `skos:ConceptScheme`, so the ledger declares no term against a Vocabulary class, and a `voc:ConceptScheme` edition fits it.
- **A pin is required only where kinds are named.** A definition that names no kind accepts every kind, and resolved none, so it pins nothing. One that names kinds pins exactly one edition, and each kind it names is a concept of it. A pin with no kinds named is not refused.
- **Foundation's warning on a quantity is answered by minting.** The sketch on accounts from instruments, section 9, rule 1, has the stated amount and the ceiling be parts of a version, minted under it. So each quantity's IRI starts with its definition's, the form `fnd:MeaningBearingEdgeShape` reads as minted under, and no quantity is shared. The parent-relative form follows [the identity guide](../../architecture/iri-identity-patterns.md) section 5.4, and LG-27's passes under their ledger. No warning remains on any example, and the tests hold that.
- **A kind is a published term of its edition.** A concept carries no identity of its own (Vocabulary, section 5.1), so the edge to it would be warned on unless the concept is versioned by something. In the examples each kind is `rdfs:isDefinedBy` its edition, the versioned scheme that declares it, which ADR-A146 treats as safe. An applied module that fills `ldg:CreditKinds` declares its kinds the same way.
- **Value spaces and recurrences gain identities.** Quantification makes both `fnd:Versioned`, and `ldg:unitOfAccount` and `ldg:periodRecurrence` now bear meaning, so the examples give them the identity Foundation asks for.
- **Foundation's check runs in the ledger's tests.** No task ran `fnd:MeaningBearingEdgeShape` on any module's examples. The tests now run it on all eighteen examples and on the corpus, with `fnd:VersionedShape` on the ledger's own versioned classes. `fnd:VersionedShape` also reports Quantification's `qnt:OperationCapability`, which is `fnd:Versioned` and carries no identity in this module's examples or any other's. That is Quantification's to answer, so the tests leave it out, and a gap is recorded.
- **Which version an account folds against is not decided.** An account names the definition version it was derived under, and that version is part of its natural key. Whether a later version reaches an account that has postings as the same account from a stated position, or as a new account, is not decided, and no example writes a second version. Section 13 records it, and it is a question below.
- **The compatibility shape is not built.** LG-12 builds it.
