# LATTICE workers

Graph-reference workers for the LATTICE semantic platform: each reads a job naming a graph by
reference (never carrying RDF or credentials on the wire), does its work, and publishes a result.
See the module docstrings under `src/lattice_workers/` for the MORK, Surface and projection jobs.

## Word authoring POC: Logical English reading (ADR-A118)

**Not a platform contract.** The reading behind the Configuration Studio's `analyse` job, for the
[Word add-in](../apps/word-authoring-addin): reads a Wording-layer graph (built from a document's markup by
the studio's service), reads each clause as Logical
English against a small sentence-form profile, and proposes the meaning it reads as an `ins:`
graph. See the
[sketch](../docs/developer/sketches/word-authoring-poc.md),
[plan](../docs/developer/plans/word-authoring-poc.md) WA6 and
[ADR-A118](../docs/architecture/decisions/ADR-A118-word-authoring-proof-of-concept.md). Its code,
vocabulary and graph layout may be removed or rewritten without deprecation. For how this worker
fits with the service, the add-in and the compose stack, including the architecture and data-flow
diagrams, see the add-in's
[README](../apps/word-authoring-addin/README.md#how-the-proof-of-concept-fits-together).

### Modules (`src/lattice_workers/wording_le/`)

| Module | Holds |
|---|---|
| `namespaces.py` | the five namespaces this job reads or writes, and the base-free IRI helpers that mint a proposal's nodes from a wording IRI |
| `offsets.py` | UTF-16 code unit conversions, since Python strings count code points but every offset on the wire counts UTF-16 units (plan §2.5) |
| `model.py` | `load_wording(graph, wording_iri)`, reading the Wording layer the Java service wrote: elements, their parts, and the document's declared variables |
| `tokens.py` | `tokenise(element)`: a variable or reference part is one token, literal text splits into words and punctuation, keeping element-text offsets |
| `forms.py` | `load_profile()`, reading the packaged `forms/sentence-forms.json`: twelve sentence forms, each a relation class, an English template and typed slots |
| `matcher.py` | `best_match(tokens, profile, element, variable_types)`: matches an element's tokens against every form, preferring the one with the most fixed words, then the earliest in the profile |
| `classify.py` | `keyword_class(tokens, element_kind)`: a fallback reading by keyword, when no form matches |
| `analyse.py` | `analyse_wording(wording, profile)`: the `Analysis` shape (without `graphView`), one reading and span set per element |
| `render.py` | `le_program(wording, element_analyses, profile)`: the elements rendered as an LE-shaped program text, for a human to read or paste into LE2's own editor |
| `proposal.py` | `proposal_graph(...)`: the proposed `ins:` relations, re-deriving each match's party, activity text and variable bindings since the `Analysis` shape itself carries only `formId`. `graph_view(...)`: the same graph as nodes and edges, for the task pane's diagram |

### Running the tests

```
mise run check:workers
```

`test_wording_le.py` tests the reading. Its goldens live under `tests/fixtures/wording_le/`: each sample's full `Analysis` object, the facility sample's LE program and its proposal graph. These are generated once by hand, reviewed, and never regenerated by a script, since reviewing the reading is the point. The Configuration Studio's `analyse` job runs the reading on a saved document (below).

## Configuration Studio jobs (ADR-A136)

The worker behind the Configuration Studio, a supported part of LATTICE (ADR-A136). It reads a job graph from Fuseki, validates or compiles the submitted vocabulary, quantification, eligibility, persistence or surface configuration against a baseline, and sends the job graph back with its status, report, artefacts and gaps as a `job-update` to the workspace's store writer, never writing the store itself. The contract is in [`contracts/config-studio`](../contracts/config-studio/README.md). Install the extra with `-e "./workers[test,studio]"`.

The runnable job: `python -m lattice_workers.config_studio_main`, consuming `lattice.studio.jobs`.

`config_studio_assembly.py` holds the contract builder's jobs (ADR-A138): `assemble_all`, which runs `tools/wording_assembler` on each `cst:Assembly` of an `assemble` job's input and gives the job's findings and artefacts and the records its update writes, and `validate_library`, which checks each form of the library against Wording's laws.

| Module | Holds |
|---|---|
| `config_studio_jobs.py` | `run_job(...)`: the pure job logic, pySHACL validation and the persistence and surface compilers, run in process. Ontology files are found through the repository catalogue reader. Surface validation skips `constraints.ttl`, which pySHACL refuses (TD-11) |
| `config_studio_layers.py` | the vocabulary resolution table, by `tools/vocabulary`'s resolver, and eligibility's compilation, expansion and question decisions, by `tools/mork_compilers`' IR and compiled SPARQL |
| `config_studio_worker.py` | `TOPOLOGY` (the packaged `config-studio-topology.json`, identical to the contract's), `ConfigStudioWorker` (`accept`, `handle`), `WriterStore`, which reads from Fuseki and publishes each job graph to `lattice.studio.writes` keyed by its workspace, `RabbitMqConfigStudioWorker` (ack after the broker confirms the final update, nack without requeue on a malformed message, nack with requeue and re-raise on anything else) |
| `config_studio_main.py` | `read_config(env)` and `main()`: connects with retry, declares the topology and the writes exchange, publishes on a channel in confirm mode, consumes with manual ack and `prefetch_count=1` |

| Variable | Required | Default |
|---|---|---|
| `LATTICE_AMQP_URI` | yes | none |
| `LATTICE_FUSEKI_URL` | yes | none |
| `LATTICE_FUSEKI_DATASET` | no | `studio` |
| `LATTICE_FUSEKI_USER` | no | none |
| `LATTICE_FUSEKI_PASSWORD` | no | none |
| `LATTICE_ROOT` | no | found from the working directory by the catalogue reader |

Tests: `mise exec -- python -m pytest workers/tests/test_config_studio_worker.py workers/tests/test_config_studio_layers.py`.
