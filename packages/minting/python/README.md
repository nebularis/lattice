# lattice-minting (Python)

Mints IRIs from a LATTICE minting recipe, as the [identity minting specification](../../../docs/architecture/identity-minting-specification.md) defines. Python 3.14 or later, standard library only, Unicode 16.0.0.

It is not published to a package index. Install it from this directory:

```bash
python -m pip install ./packages/minting/python
```

## Minting

```python
from lattice_minting import Recipe, Minter, MintError

recipe = Recipe.parse(open("Product-EntityRole-38ce5a73f929.recipe.json").read())
minter = Minter(recipe)
minted = minter.mint({"key": [" Widget-9 "]})
minted.iri     # 'urn:ex:sku:XARXQP2R47P6MPFLTVC422KYQSO6EFWM'
minted.trace   # every intermediate value, in the vectors' trace format
```

`Recipe.parse` verifies the recipe's format, digest and Unicode version before anything is minted. The request's inputs are the members listed in [§6 of the specification](../../../docs/architecture/identity-minting-specification.md#6-strategies). A refusal raises `MintError`, whose `kind` is one of the named errors of §9:

```python
try:
    minter.mint({"key": ["   "]})
except MintError as e:
    e.kind     # 'EmptyKeyComponent'
```

### Claimed identity

Pass the claim secrets as bytes, keyed by the recipe's `keyId`. The minter does not keep a reference to your mapping, log it, or return it. Fetching and rotating secrets is yours to do ([§8](../../../docs/architecture/identity-minting-specification.md#8-secrets)).

```python
minter = Minter(recipe, secrets={"example-key-v1": secret_bytes})
minted = minter.mint({"key": ["Ada@Example.org"], "scope": "acme",
                      "surrogate": "8f2c1b7e-3e4a-4f7c-9a6d-2b1e0c5d7f90"})
minted.iri, minted.claim_iris
```

### Content-addressed identity

> **The minter hashes the bytes you give it. It does not canonicalize RDF.** You must meet the caller's obligations CA-1 to CA-4 in [§7 of the specification](../../../docs/architecture/identity-minting-specification.md#7-content-addressed-identity-the-callers-obligations): a conformant RDFC-1.0 implementation, the self-reference rule applied first, the work budget enforced, and the full digest verified where the recipe says so. Two callers who canonicalize differently mint different IRIs, and nothing here can detect it.

The request must name its canonicalizer, or the minter refuses with `CanonicalizerNotDeclared`:

```python
minter.mint({"canonicalNQuads": nquads, "canonicalizer": "your RDFC-1.0 implementation and version"})
```

### Random surrogates

`Minter(recipe)` uses `secrets.token_bytes`. The `randomHex` input and the `random_bytes` argument exist so that vectors and tests can fix the randomness. Never use either in production.

## Conformance

```bash
lattice-mint verify contracts/identity/anchor-vectors.json packages/minting/testdata/*.vectors.json
```

Or from Python, `lattice_minting.verify(path)` returns a report with `passed` and `failures`. Each failure names the first trace step that differs.

`lattice_minting.vectors.generate(recipe)` produces a vectors document for any recipe. `persistence export-recipes --vectors` uses it. Vectors generated by this library can only show agreement with it, which is why every implementation, this one included, must also pass the independently verified anchors.

## Tests

```bash
mise run bootstrap:minting-python
mise run check:minting-python
```

The suite runs the anchors and every generated vectors file, checks that the committed vectors are what the library generates today, cross-checks the Unicode tables over all code points against CPython's Unicode 16.0.0 data, and checks that every pipeline is idempotent.
