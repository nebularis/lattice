Scope

submission/ packages an exposure set version, requirements and existing cover for one placement. claims/ records claims, loss cause chains and the filling of claimant, harmed and payee roles against the responding contract.

Changed by CCS (2026-09-30). A claim is a case for the responding policy’s relations, and its handling is a set of occasions in Behaviour (computable-contract-substrate tranche D): notice as a condition precedent, advancement duties, relation back as a deeming, and parties resolved per claim.

Invariant: a submission cites one exposure set version and the requirements and existing cover of that version, records which insurers were approached and how each responded, and records what each insurer asked for. Information gaps are derived from the data, never authored, and adding data only ever closes gaps.

AIR-6.1-Q1, how much of the earlier designs’ question bridge. Decided: information requests, answers as assessments, and gaps as derived artefacts, as below. Not the earlier designs’ answer types (an attribute type’s value form already says what an answer looks like), placeholders (an open request is the placeholder), remediation actions and client request packages (workflow, which belongs to a consumer), or inference rules (derivations are code in tools/, as AIR-4.3’s are). A submission is a new version when the exposure set version it cites changes, so an insurer’s quote always refers to the data it saw.

A decline here is a response to this submission. When it should count as cover history (AIR-4.4’s Declined) is the broker’s judgement, recorded there as its own evidenced fact, and the notes say so.

Code (tools/submission_gaps.py)

gaps(graph, submission, run) returns the gaps as a separate graph: for each open request asking for attribute types (directly or through a family’s profile shape), each subject of the cited exposure set of the right kind with no value of that type in any assessment, and for each peril in the scope of a cited requirement, the relevant attributes AIR-4.2’s completeness shape would warn about. Gaps are derived, so answering a request is adding an assessment and re-running the function, never editing a gap.
