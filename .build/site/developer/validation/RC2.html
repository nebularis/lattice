Validation Pack: RC2, the tools read the repository catalogue

Unit: improved-ontology-documentation, slice RC2 (plan). Implements: ADR-A121’s first two consequences, for the five tools the plan names. Decisions needing confirmation: two implementation choices, below.

Invariant

Each fact the five tools held as a constant or took as an argument is now read from the catalogue, and the tools behave as before. Every extraction yields the same files, the import guard judges the same layers by the same order, the versioning check reads the same directories, and the freshness check compares the same Isabelle output.

Implementation choices, for the maintainer

  1. The extractor finds the catalogue from the working directory or LATTICE_ROOT, never from --root. --root keeps meaning where outputs are written or compared, so a test that copies a layer into a temporary directory and checks it there still works (Eligibility’s hand-edit test does).
  2. The catalogue is read only when a shape block names no file. A README outside the catalogue with no such block still extracts, which keeps OD1’s temporary-README tests and any downstream use working without an entry.

One command

Run from the repository root. A pass is every test passing, with no skip, and the suite otherwise passing as before:

mise run check:ontology-catalog

Then the four tools’ own checks. A pass is each passing as before:

mise run check:import-guard && mise run check:ontology-versioning && mise run check:formal-freshness && mise run check:catalogue

Deliberate non-coverage

  • PROOFS_ROOT and REFERENCE_ROOT in the freshness check, and other tool-to-tool paths. Tool packages and their paths enter the catalogue in RC3.
  • Other tests that load a layer’s shape files to validate graphs (for example LAYER / "shapes" / "structural.ttl"). They read files and do not state the extraction contract. The bypass scan of RC3 lists them.
  • The import guard still judges only the substrate. Applied entries can state imports when a later change extends the guard to them.

Results

2026-10-18, after merging main: the four tools’ checks pass. The import guard finds no violation across 8 substrate layers, the versioning check finds no unbumped change and no missing release row, the freshness check finds 2 artefacts consistent, and check:catalogue finds 19 modules agreeing with the tree. check:ontology-catalog then passed, 974 passed and 7 skipped in 47.49s, with the XML catalog consistent and its 2 known defects reported. Neither RC2’s tests nor OD1’s carry a skip marker, so the 7 skips are the reasoning tests that need the reasoning-testkit jar (ADR-A83), which is not built in this worktree. The two implementation choices await the maintainer’s confirmation.

Implementation choices, answered

2026-10-18, by the maintainer.

  • RC2-C1, option (c). The extractor reads the catalogue nearest above the README, passed to the reader as its explicit root, and falls back to LATTICE_ROOT and the working directory only when there is none above it. Implemented the same day as lattice_repo_catalogue.root_above() and contract_shapes(..., readme), with test RC2-T7 (the extractor run from a directory outside the repository). Choice 1 above is superseded.
  • RC2-C2, option (a), as implemented. The move to option (b), every extraction reading the catalogue and failing when a README’s generated files differ from its entry, is planned for after RC4, when every extracted README belongs to some catalogue. It is recorded in RC4’s row of the plan and in the extractor’s contract_shapes() docstring.

RC2-T7 is authored, not yet run.
