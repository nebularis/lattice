Validation Pack: FMH-H2.4a, the composite family’s builders

Unit: formal-methods-track-h, slice H2.4a, planned in plan §4.2 under ADR-A123 and its addenda. For countersignature (non-weakening rule): one item, below. Open decisions: none.

Invariant

The six composite templates render the query their builders do, apart from the guard. A replace or tombstone with no $root writes nothing. Every ported operation of every family can be encoded structurally and decoded to an equal value, builds equal twice, and builds without reading a file, the clock or the environment (SI-1, SI-2), so a stored IR stays possible (PDD-06).

What changed

  • Six templates ported in builders.py: create-if-absent-composite, cas-replace-composite-property and tombstone-delete-composite, each with its dataset-guard variant. The path is read with Bindings.path, the data graph with b.graph("dataGraph"), and the receipt’s ?logGraph2 is kept (plan §4.2, fact 4). The replace and tombstone share their WHERE with the named-graph writers through _row_where, which now takes the sweep as an argument. The harness covers the new stems, and the harness, binding, guard and role cases (H2.2-T1 to T6, H2.3-T32) run over them.
  • test_composite_builders.py, 14 cases, below.
  • Nothing in instantiate, the CLI or the IR changed.

For countersignature

Test inputs changed in three files (test_composite_boundary.py, test_composite_lifecycle.py, test_composite_sweep.py). They bound $epoch as an xsd:integer, and stored the row’s and the dataset graph’s epoch the same way, so the request matched the store by term. The composite operations now carry the parameter guard, which refuses an xsd:integer epoch (the README says it is a different term and never matches), so the request and the stored epochs are xsd:long. The assertions are unchanged. This is the same change as FMH-H2-3’s second countersignature item, now for the composite tests.
