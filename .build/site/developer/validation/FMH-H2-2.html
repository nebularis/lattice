Validation Pack: FMH-H2.2, the equivalence harness and the first builders

Unit: formal-methods-track-h, slice H2.2 of the typed IR sketch §7 and its §7.1, under ADR-A123 and its addendum of 2026-10-12. Decisions needing confirmation: none. Decision 1 was decided on 2026-10-12, and the maintainer accepted decisions 2 and 3 on 2026-10-12.

Invariant

A builder renders the query its Mustache template does, apart from the required-parameter guard, and the guard turns a missing or mistyped parameter into no write (TD-34). “A port changes nothing, and a change ports nothing.”

What changed

  • persistence/builders.py: bootstrap-version-row and append-event, each with its dataset-guard variant, as typed Operation values built from the same compile-time bindings a template takes (BUILDERS, build). Each keeps the template’s variable names. The builders take the guards flag (guards=False gives GUARDS_OFF).
  • tests/equivalence.py: the harness. Both sides are parsed and translated to algebra by rdflib. Only the triples of a basic graph pattern and the conjuncts of a filter are put in order. Variable names must match. It also checks that a builder reads exactly the bindings its template uses, and that it compared as many operations as were ported.
  • instantiate renders a ported operation from its builder, with the guard, and any other operation, and any operation under --template-dir, from Mustache as before. persistence instantiate --no-parameter-guards leaves the guards out. operation_context is now shared with the builders.
  • Kind.IRI_OR_LITERAL and the function ISLITERAL in the IR (decision 1).
  • The first port of append-event differed from its template, in an epoch triple I put in the non-dataset INSERT. The harness caught it before any other test did, and the builder was corrected.
  • TD-34 is partly closed. Its register row says which operations are done.
  • After the review (2026-10-12). A builder no longer chooses a graph role. GRAPH_ROLES in builders.py gives the role of every graph by its binding name (txnGraph, metaGraphPrefix and the rest) or by the name of the variable a query binds to a graph (g, log, logGraph, logGraph2, eventGraph, each with one meaning in every template). Bindings.graph(name) and graph_var(name) are the only ways a builder makes a graph. Before this, a builder that put the transaction graph in the META role passed every test, since a role is not rendered and only the derived read and write sets carry it.
  • After the review (2026-10-12). operation_context wraps each binding as the term type its dal:paramType declares (Iri, Literal for String and Literal, PropertyPath, or an int), and refuses an unknown type. Before this, Bindings.const guessed the type from the text’s first character, which would have read a composite family’s ownedPath as an IRI in H2.4. A path binding is now read with Bindings.path, and const refuses one.
  • tests/equivalence.py imports at module level, and two unused imports are gone.

Decisions needing confirmation

  1. Decided 2026-10-12. $occurredAt is a new kind, IriOrLiteral, guarded by isIRI || isLiteral. It was named Term when first built and renamed the same day, since a term includes blank nodes and Term means something else in instrument. The kind is a Python enum value, not an ontology class. The valid time of an event is an adopter’s own value and the README does not type it, so a DATATYPE test could refuse a date an adopter uses today. The guard still catches a missing value. The maintainer agreed to keep it untyped as to datatype. A datatype taken from the family’s declared valid-time property is possible in H2.7.
  2. Accepted 2026-10-12. instantiate now uses the builders for the four ported operations, so the shipped .rq of those operations carries the guard. That is what closes TD-34 for them, and the S-3 and S-4 checks and the witness harness pass over the new text. The flag is on instantiate for now. The addendum puts it on compile, recorded in the profile, which needs the dal: term of H2.7, so the flag moves then.
  3. Accepted 2026-10-12. The harness corpus is every fixture that compiles, the examples and the witnesses, not the examples alone. Between them the four templates are generated 5 times, so five comparisons run. A template that no fixture selects is not compared (T1 fails first, so a gap cannot hide).

  • Text-substituting callers for the builders. H2.1’s T28 substitutes text into an IR operation and runs it. No test does that for a builder’s output yet.
