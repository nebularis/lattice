Invariant

One append request, however many events it carries, steps the stream’s seq once and writes one version row, one txn claim and one receipt, and every event it writes names that receipt. The result does not depend on the order in which a store applies the solutions. A declaration of a receipt model the generated operations do not honour is reported, never silent (H1.4c).

What changed

  • The IR (ir.py, ir_render.py). A Rows slot kind, RowsSlot and RowValues. The checker takes the variables of a RowValues as definitely bound and refuses a wrong slot kind, an undeclared parameter and an invalid variable name.
  • Templates and builder. append-event and append-event-dataset-guard read their events from VALUES (?event ?eventType ?opSeq ?occurredAt) { } } and write } beside them. The parameters $event, $eventType, $opSeq and $occurredAt are gone. The builder and the template still agree under the equivalence harness. append-event is builder version 2.
  • The contract. DigestContract gains event, the sources of an append’s event part (the two slots). An append has no payload part. The part leaves out pat:revision. H2.8 computes it.
  • The warning. compile warns ReceiptModelNotHonoured, naming the model, for dal:PatchLog and dal:SnapshotPerRevision. A witness exists for each (warning-ReceiptModelNotHonoured.ttl, snapshot-ReceiptModelNotHonoured.ttl), each on a scope of higher priority than the base’s.
  • Documents. ADR-A123 addendum (draft), guide §15.2 dated note, README, TSD-21 in the triple-store record, this pack, the status record, the plan and the index.

Findings

  • TSD-21. rdflib 7.6.0 raises AttributeError for an empty VALUES block in an update WHERE, before it changes anything. Oxigraph gives no solution. Recorded in the triple-store record. Nothing is written on either store, and H2.8’s caller check refuses an empty slot before sending.
  • Cost of the event triples (TD-42). Each row writes the same ground eventTriples, so k rows cost k × |eventTriples| fills over one set. This is the quadratic fill of TSD-02 and is not measured here.
  • The parameter guards no longer see opSeq or occurredAt, which are row values. This is the deliberate non-coverage of the plan, closed by H2.8.

Adversarial probes

Each was run on the finished tree and then reverted.

  1. The VALUES block moved into a group of its own (the plan predicted the three-row test would fail). It did not. All 57 selected tests passed, because a group that holds only a VALUES block joins with the rest of the WHERE exactly as the bare block does. The plan’s prediction was wrong and we found no form of this change the tests catch.
  2. A mutation that makes the receipt depend on the event (?opSeq added to the log graph name). T1 and T7 fail on all four engine and guard combinations, because three receipts are written. This is the probe that tests the invariant.
  3. The digest parts declared in another order (ExpectedSeqPart before TargetPart). check:persistence-expected-profiles reports the five files stale.
  4. A patch-log profile that compiles without the warning. T11 fails for the patch-log witness, and the witness-coverage tests (test_h1_2_t15, t16, t23, t27, t28) fail.

Deliberate non-coverage

  • Checks on the slots’ content: subjects bounded to the batch’s events, distinct opSeq values and a non-empty eventRows (H2.8).
  • The digest computation itself (H2.8) and the parts for the held patch-log half.
  • The held patch-log half, snapshot receipts, H2.10, H2.7 and H2.8. Nothing of them is built here.
  • Fuseki and the other stores. Only rdflib and Oxigraph are measured (TSD-Q12).
