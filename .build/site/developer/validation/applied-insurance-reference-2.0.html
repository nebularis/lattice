  • Deviations from the plan:
    1. Found a real, generalisable bug while regenerating: tools/literate_extract.py’s target.write_text(content, encoding="utf-8") (no newline= argument) lets Python’s text-mode write translate embedded \n inside a multi-line SPARQL string literal to \r\n on Windows, changing that literal’s value, not just insignificant whitespace. Fixed with newline="\n". Unrelated to AIR but found and fixed in the same file this slice already touches.
    2. Verifying the conversion’s isomorphism against HEAD found rdflib.compare.to_isomorphic/ graph_diff unreliable for peril/shapes/constraints.ttl, which has several sh:NodeShapes sharing the same local blank-node shape around sh:sparql. Verified instead with a deterministic skolemization (each shape’s sh:sparql blank node renamed from its own IRI plus the sorted order of its sh:message text) before a plain set comparison. Both methods and scripts are recorded in session memory, not committed (one-off verification aids).
    3. prl:DocumentationShape is placed in shapes/constraints.ttl, per the brief, even though its per-concept shape resembles structural.ttl’s convention more closely. Noted, not changed, since the brief is explicit.
