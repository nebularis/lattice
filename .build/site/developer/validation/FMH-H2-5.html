Validation Pack: FMH-H2.5, key claims, the audits, guard D and the SELECT fragment

Unit: formal-methods-track-h, slice H2.5, planned in plan §4.3 (H-D23, one slice in six gates) under ADR-A123 and its addenda of 2026-10-13. For the maintainer: all three decisions were taken on 2026-10-13, and 1 and 2 are built in this slice. Nothing is open. The stop condition on P5 did not arise. For countersignature (non-weakening rule): none. No test was removed or loosened. Two existing tests changed their expected text to follow the guard (below).

Invariant

Each of the ten remaining templates (five key-claim operations, five audits) has a builder that does what its template does, held to it by the equivalence harness. An operation built with its parameter guard writes nothing when a required parameter is missing or mistyped, on rdflib and on Oxigraph alike. The SELECT fragment of the IR refuses the forms that are illegal SPARQL or fail without an error (ADR-A123, addendum of 2026-10-13). A difference between the two stores that changes a result is found by a test and recorded in the triple-store record, and not left to a review.

What changed

  • Guard D (gate 1). _guard_expr writes DATATYPE($p) = DATATYPE("0"^^xsd:long) for Long and Position. A new parameter kind, Literal, is guarded by isLiteral($p) && LANG($p) = "", for the retire time. An operation with no required parameter gets no guard group.
  • The SELECT fragment (gate 2). SubSelect(select, where) is a pattern element. Select serves a query and a sub-select, and has four more fields (distinct, order_by, limit, offset) that exist so the checker can refuse them with a named rule. The checker has four new rules, UngroupedProjection, HavingNotGrouped, SubSelectLeak and FragmentLimit, and the boundness table of the plan for a sub-select’s projected items. Every walk enters a sub-select (reads and writes, roles, clock variables, boundness, the guard’s place). A sub-select starts with nothing in scope, and inside a GRAPH block it reads that graph.
  • Merge-rewrite takes IRI(MIN(STR(?owner))) (decision 1), in the template and the builder.
  • Ten builders (gates 4 and 5) in builders.py, registered in BUILDERS. Every template apart from cas-replace-value-guard (TD-43) is now ported. ?other and ?canonical are declared Kind.IRI, with the data invariant from the patterns guide recorded in the builder. The gap scan declares ?seq, ?S and ?L as Compare.VALUE.
  • The renderer writes the parentheses of every nested arithmetic operand (TSD-17), and SELECT DISTINCT for a top-level query. The gap-scan template says (?S - ?L) + 1 for the same reason (decision 2), so the harness needs no normalisation for it.
  • The tests’ engine axis. engines.guards() is now on for both engines. @engines.each_engine_and_guards runs a behaviour test with the guards on and off (the guard_axis fixture), on both engines. 61 behaviour tests across seven modules have the axis, which doubles each of them. The guards-off cases are kept, since --no-parameter-guards stays supported.
  • Documents. Triple-store record TSD-15 to TSD-20, the consequences of TSD-07 updated, TSD-Q6 to Q10 answered and TSD-Q11 and Q12 added. TD-34 removed from the debt register and TD-43 and TD-45 updated. The README of tools/persistence describes guard D, the fragment and the ten ports.

The golden text that changed (gate 1, step 2)

Every operation with a Long or Position parameter has a changed guard line, DATATYPE($p) = xsd:long becoming DATATYPE($p) = DATATYPE("0"^^xsd:long). That is bootstrap-version-row, append-event, the named-graph and composite create, replace and tombstone, and each dataset-guard variant. Three files pin the text, and each changes in that one line only: tests/fixtures/ir/base-operation.rq, replace-named-graph.rq and replace-named-graph-caller.rq. The guard-position test (H2.2-T6) expects the new form, and expects no guard group at all for an operation with no required parameter.

Decisions needing confirmation

  1. Decided 2026-10-13: option B, built in this slice. Merge-rewrite on rdflib (TSD-16). The port equalled its template, so on rdflib it wrote "urn:o:1" as a plain literal and linked the canonical owner to itself, and on Oxigraph it wrote IRIs. Both picked the same owner. Options were:

    Option Consequence
    A. Keep it as a port, with the difference recorded Nothing to build. A deployment on rdflib gets literal links and a self-link
    B. Compute the canonical owner as IRI(MIN(STR(?owner))) An IRI on both, and the self-link goes since ?other != ?canonical then compares two IRIs. A change and not a port (typed IR sketch §7.1), so the template changed with the builder and the harness still holds them equal
    C. As B, plus a shape that the merge relation’s objects are IRIs B, and the property is checked in the data. A shape on the adopter’s merge relation belongs with H2.7’s vocabulary

    Built: the template and the builder project IRI(MIN(STR(?owner))). The checker now lets an aggregate sit inside a scalar function of a projection (and still refuses one inside another aggregate), and the boundness rule follows the function (IRI(MIN(...)) is bound with a GROUP BY and not without). H2.5-T29 and T30 now hold on both engines with no engine branch: links to the lowest owner, none to itself, all IRIs. Option C stays with H2.7.

  2. Decided 2026-10-13: option B, built in this slice. How the builder and the template agree about arithmetic (TSD-17). Oxigraph groups ?S - ?L + 1 from the right, so the gap scan’s template, written as a chain, counted wrongly there. We first made the renderer write the parentheses of every nested arithmetic operand and made the equivalence harness read a left-nested chain as the flat one it equals. Options for the template were:

    Option Consequence
    A. Keep what was built The harness keeps one normalisation beyond reordering what SPARQL leaves unordered, and the template stays wrong on Oxigraph until H2.9
    B. Parenthesise the template as well, and remove the harness normalisation Template and builder agree as text, the harness only reorders, and the known defect leaves the legacy path
    C. Render the chain flat, as the template had it The gap scan reports every complete stream as a gap on Oxigraph

    Built: the template says (?S - ?L) + 1, the harness normalisation is removed, and test_h2_5_t47 now also fails a builder that groups the sum from the right. The alignment test that pins the template text follows. The renderer’s rule stays.

  3. Decided 2026-10-13: fine for now. Select carries distinct, order_by, limit and offset so that each can be refused with FragmentLimit.** That gives the plan’s “each with a refusal test”, at the price of four fields nothing uses. The alternative is no fields, and a limit that is simply unrepresentable and untested.

Deviations from the plan

  • The harness gained no normalisation. A first version read a left-nested arithmetic chain as the flat one, and decision 2 removed it by parenthesising the template. Aggregate names did not need one either, because the builders emit the aggregates in the template’s order and the equivalence holds.
  • Gate 1, step 4: the axis is a fixture and a marker, not a duplicate of each test. The behaviour tests that assert the guard itself take guards= explicitly and are unchanged.
  • The boundness table names SUM and AVG, which are not in the fragment’s function set, so only COUNT, MIN, MAX, SAMPLE and GROUP_CONCAT are implemented. Adding the other two is a line in AGGREGATES and a rule that their argument is numeric.
  • The four unknowns of the plan’s fact 10 are answered (MIN over IRIs, COUNT(DISTINCT) over mixed terms, the arithmetic, GROUP_CONCAT’s order) and TSD-Q6 to Q10 are closed. Two new questions, TSD-Q11 and Q12, are open.

Deliberate non-coverage

  • cas-replace-value-guard (TD-43, H2.7’s vocabulary).
  • The caller-side checks, including the strict xsd:long check (NQ6) and logGraphs, in H2.8. An empty logGraphs makes the gap scan check only the pinned graph, and it reports clean for a stream whose receipts are all in buckets. A caller obligation for H2.8 and an applicability label for H9.
  • An ill-typed literal such as "99999999999999999999"^^xsd:long, which keeps its datatype on rdflib and passes the guard. H2.8’s check.
  • Binding over the SPARQL 1.1 Protocol, which no engine here offers in process.
  • COUNT(?owner) in quarantine counts solutions and not distinct owners, which is right while one keys graph holds the claims (TD-06, TD-41).
  • How the canonical owner of a merge is chosen beyond MIN (NQ5). T30b records the property that a lower owner joining later changes it and earlier links stay.
  • SUM, AVG, ORDER BY, LIMIT, OFFSET, DISTINCT inside a sub-select, and nested sub-selects, which the fragment refuses.
  • Stores other than rdflib and Oxigraph (TSD-Q12).
