Validation Pack: FMH-H2.1, the typed operation IR and its renderer

Unit: formal-methods-track-h, slice H2.1 of the typed IR sketch §7, under ADR-A123 (accepted 2026-10-10). Decisions needing confirmation: the four below were confirmed by the maintainer on 2026-10-10. Two questions from the review remain, under “Review, 2026-10-10”.

Invariant

An operation that the types of persistence.ir forbid is never rendered. Each hazard of the specification sketch §3 is a named refusal, and any value that is accepted renders deterministically to SPARQL that parses as exactly one operation, whatever literal or IRI an adopter supplies (ADR-A79 point 5, ADR-A123 decision 2).

What changed

  • persistence/ir.py: the values. Operation, Param with a Kind, the terms (Var, ParamRef, Const), Graph with a mandatory GraphRole, GraphBlock, the pattern forms (Optional_, NotExists, Bind, Filter, Values, Union_, Group), the expressions (Func, Op, Not, TermGuard, ValueGuard), Select, and the derived ParameterGuard. A Const takes only an Iri, Literal or Integer from terms.py, so a bare string or a blank node cannot be built.
  • persistence/ir_render.py: check (the 26 refusals of RULES), render, and access_sets, which derives the graphs and subjects read and written from the same walk. Nothing in compile, instantiate or the templates calls either module yet. The builders arrive in H2.2 to H2.5.
  • persistence/namespaces.py: PAT, the patterns vocabulary the templates declare as pat:.
  • persistence/terms.py, a defect fix outside the slice’s module list (decision 1 below). Literal.encode wrote a literal containing a backslash before u or U so that SPARQL’s whole-text \u escape processing mangled it.
  • Tests: test_ir.py, test_ir_render.py, ir_fixtures.py, a pinned rendering in fixtures/ir/, and two cases in test_terms.py. The README describes the IR and marks it unused.

Decisions needing confirmation

  1. Literal.encode changed. The H2.1 property test T21 found that a literal value such as A is encoded as "\\u0041", and rdflib’s preprocessing of \uXXXX escapes then turns it into a syntax error. SPARQL 1.1 §19.2 defines the preprocessing over the whole query text, so a conforming engine may do the same. The fix writes the u of such a pair as its own escape and the hex digits after it as escapes (rdflib reads up to eight digits after \u). Every previous encoding is unchanged. This touches the injection boundary of ADR-A79 point 4, so it is listed here for your review, not folded in silently. The corpus in test_terms.py still passes.
  2. Comparisons are guards, and a value comparison needs a declared kind. An Op cannot compare. A ValueGuard on a term-matched Var or Param is refused unless its kind is Iri, so a builder declares Compare.VALUE on a position it reads through FILTER (the fence, the gap scan’s seq). This is how the brief’s “a position is declared term-invariant or value-compared” is made checkable. An undeclared variable counts as term-matched.
  3. Rules beyond the hazard table. UnboundGraphVariable (a GRAPH ?g in WHERE must follow the BIND or VALUES that binds ?g, the “unbound GRAPH ?g” row), BindTargetInScope (a SPARQL error that rdflib does not raise), UnusedParameter and NameCollision (a variable named as a parameter). Each fires on a mistake a builder could make in H2.2 to H2.5.
  4. Not built, left to the slice that needs it. A sub-select (key-claim-merge-rewrite, H2.5), UNION with VALUES for the payload (R2 of the brief, a change and not a port), and Position width rendering (the append template pads in the query text).

Confirmed 2026-10-10. The maintainer accepted all four as written: the Literal.encode fix, comparisons as guards with a declared kind for a value comparison, the rules beyond the hazard table, and what is left to later slices.

Correction found while planning H2.3 (2026-10-12). One of F4’s three refusal cases, “GRAPH ?g in an OPTIONAL after an outer BIND of ?g”, is wrong in intent. A BIND inside an inner group cannot see ?g, but a pattern’s solutions are joined with the enclosing group on ?g, so the result holds only ?g’s triples and does not range over every graph. Three shipped templates rely on it. H2.3a changes the rule and moves the case to the accepted ones (plan §4.1, H2.3-Q2).

Also removed: two unused parameters of the walk (top, indent), one that changed nothing (in_graph), a set that was written and never read (var_names), and a function-local import.

R1 and R2, settled 2026-10-12 by the ADR-A123 addendum. Guards are optional and on by default. An operation carries the derived guard or GUARDS_OFF, and check refuses one with neither (R1). The guard is a type test per parameter, isIRI for an Iri, which also catches a missing parameter and survives text substitution (R2). The compile flag, its dal: term and its INFO diagnostic land in H2.2, H2.7 and H2.8.

Not changed, recorded for the slices that meet them: an optional parameter used directly in a template triple is not tagged and can be skipped silently (no shipped template has one), and NOW() reaching a guard through a pattern, such as FILTER NOT EXISTS { GRAPH ?logGraph { ... } } with a clock-derived ?logGraph, is not ClockInGuard.
