  • Deviations from the plan:
    1. Seven voc:SchemeContracts added, each with fnd:hasIdentity/fnd:hasGovernanceState and bound by voc:boundScheme, following insurance/common’s own pattern exactly: the brief’s table named the reference concepts per property but the actual contract declarations were implicit. Built to match AIR41-02’s own test case (“the seven contracts / Vocabulary’s shapes / conform, each bound to its reference scheme”).
    2. Every shape uses sh:sparql, never sh:property. An initial draft used sh:property for simple cardinality rules, but sh:sourceShape for a sh:property violation names the anonymous nested property shape, not the enclosing named NodeShape — a real difference from insurance/peril’s shapes, which use sh:sparql throughout and were the house pattern this slice should have followed from the start. Rewritten so every violation’s sh:sourceShape is the named shape the table (§6) describes, consistent with peril/’s convention and this module’s own tests.
    3. Two bugs found and fixed while writing the SHACL-SPARQL and before any commit: a self-contradictory FILTER pair in the valuation either-or rule (asserting a condition then immediately its negation, which could never match), and a property-path cycle check (aeo:controlled/^aeo:controller) that assumed aeo:controller/aeo:controlled are direct entity-to-entity edges, when they are properties of the reified aeo:ControlRelation node. Fixed to (^aeo:controller/aeo:controlled)+, which composes one “controls” hop correctly before taking its transitive closure. Caught by AIR41-07 and AIR41-08 failing on first run, not by inspection.
    4. PublicFoundation, not Foundation, names the legal-form concept (brief’s own table says Foundation): Foundation would collide with the substrate layer’s own name in casual reading of this README’s prose, so the concept is named distinctly while its skos:prefLabel stays “Foundation”.
