Validation Pack: OD5, the generated regions

Unit: improved-ontology-documentation, slice OD5 (plan). Implements: ADR-A126 decision 7, and decision 8’s generated marker. Built autonomously, at the maintainer’s request of 2026-10-18. The decisions taken alone are listed below, for the maintainer to keep or overrule.

Invariant

A README in the layout holds its Axiom Index (in 6.7) and its class diagram (in section 4) in generated regions, written from what section 6 compiles to, and never edited by hand. Extraction rewrites them, and --check reports a README whose regions are out of date. The regions are not read as section 6, so refreshing twice changes nothing, and they do not depend on the order of entries.

What changed

  • tools/literate_grammar.py:
    • Views reads the compiled statements and restriction rows and writes the Axiom Index and the class diagram.
    • manchester() writes a term back in Manchester syntax.
    • verbalise() puts a restriction in the diagram’s words.
    • refresh() rewrites the README’s regions, each required once in its place.
    • Compiled gains the refreshed README.
  • tools/literate_extract.py. main() writes the refreshed README, or reports it as drift under --check.
  • tools/test_literate_grammar.py. Tests OD5-T1 to OD5-T7. The helpers add both regions, which a migrated README now needs.
  • tools/test_literate_extract.py. OD1-T11’s README gains both regions.
  • docs/architecture/literate-specifications.md. The generated views are described as built.

Decisions taken alone, for the maintainer

  1. Both regions are required, once each, the Axiom Index inside 6.7 and the diagram inside section 4. A region of another name is refused.
  2. The README is an output. The extractor writes the refreshed README to the path given, not under --root, and --check lists it as drift.
  3. The views are derived from the compiled statements, plus the restriction rows, which also carry the SHACL-only rows. So they show what the grammar wrote, not a second reading of the README.
  4. The Axiom Index’s columns are Term, Kind and Summary. Terms are sorted by kind (class, object property, datatype property, individual) and then by name. A summary is short sentences in a fixed order, with restrictions sorted, so reordering a table’s rows changes nothing. Annotations are left out, since they are in the entries.
  5. The diagram’s conventions, from the maintainer’s walkthrough of 2026-10-15:
    • restrictions are members in ORM-style words, with numbers to ten written out
    • a datatype property with a domain is a member name (range)
    • an object property with named domain and range is an arrow
    • a property with no named domain is a box of its own
    • subclassing is <|--, including to classes outside the module, which appear as empty boxes
    • there are no composition arrows
    • a domain or range that is an expression is left out of the drawing, and stays in the index
  6. Names in the diagram are local names, qualified as prefix_local where two classes share one. Mermaid reads code (xsd:string) as a method, so it is drawn as code(xsd:string). It still reads correctly.

Decisions answered

2026-10-18, by the maintainer: decisions 1 and 3 to 6 agreed. Decision 2 (the README as an output) agreed after a detailed explanation. Only what lies between a generated region’s markers is rewritten. Everything else in the README is its source, so a concept is added by writing its entry in section 6, and the next extraction writes its Turtle and its place in the Axiom Index and the class diagram.
