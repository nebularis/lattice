Validation Pack: CCS HQ-6a.2, closures in the compilers

Unit: computable-contract-substrate Machine: R. Branch: ccs/hq6a2-closures-compilers, examples first (ADR-A-C2, commit 0869d43b) Plan: CCS plan, “What HQ-6a.2 builds” Decisions: HQ6a2-Q1 (1), Q2 (i) and Q3, answered 2026-10-12. ADR-A105 and its 2026-10-12 addendum

Invariant

The compilers decide as the reference semantics does (HQ-6a.1). A set reading decides on completeness, elg:SomeValue Denied and elg:EveryValue Permitted, the empty case included, only when its binding names a closure in force at the resolution instant. Without one, such an outcome is Undetermined with exe:NoClosureLicence, or the diagnostic of an undetermined value, or exe:MissingCandidate for no value. A binding naming something that is not a closure, or a closure with no source, is refused at compile time. A SPARQL row names the closure exactly when completeness decided it, before negation, and a profile row names the union of its conditions’ closures. The compilers mint no decision records. SWRL and OWL output is unchanged.

Deliberate non-coverage

  • Minting the decision record, its cut and identity, and copying ?closure into elg:closureReliedOn: C12.
  • SHACL reliance. SHACL reports violations only, so it agrees on decisions and names no closure (HQ6a2-Q1).
  • The differential harness does not yet check the ?closure column. It reads single-value readings only, and takes reliance up when it covers bound conditions (track B).
  • Closures over a period, anchors, supersession by a late fact and a closure’s binding to the store: HQ-6b. Set comparisons over closures: C9b3.

Handoff

Built (commit 349ccfa2, after the examples commit 0869d43b, then fixed at verification as below):

  • Executable 0.7.0 with exe:NoClosureLicence. Only the catalog imports Executable, so there is no cascade. The catalog and release register regenerated, adding only Executable’s rows.
  • The IR: an evidence path carries its binding’s closure. A binding naming a non-closure, or a closure with no elg:licensedBy, is refused. A closure on a single-value reading is ignored. A closure whose source states fnd:validFrom is in force only from it, and compiling then needs an explicit resolution instant. namespaces.py gains FND.
  • SPARQL: every condition query projects ?closure. _read_set decides on completeness only under a closure, counts a subject’s exe:MissingCandidate row as no value, and reports exe:NoClosureLicence when an open binding cannot decide. Negation carries the column. Profile rows project ?closures, the space-separated union.
  • SHACL: unchanged in code. Its decided shapes wrap the SPARQL backend’s condition select, so they take up closures with it.
  • The reference: decide_condition_with_reliance, with decide_condition now delegating to it, its behaviour unchanged. The package README names it.
  • test_closure_readings.py: HQ6a2-08 reads ?closures through a new sparql_profile helper, comparing sets. Its expected closures are unchanged.

Deviations from the plan:

  • build:mtp moves no pins. The MTP pins hash MORK’s own terms (Mork.ttl), and Executable is not among them. The build reported the pinned graph hash unchanged, and pins.lock.json did not change.
  • No SHACL backend change, for the reason above.
  • Three fixes found at verification, after the maintainer accepted 349ccfa2:
    • profile_select had an unterminated string, so sparql_backend.py did not import. The quote is corrected.
    • AIR32-08 (test_set_readings.py, an interval read EveryValue) still expected an open binding with every value Permitted to be Permitted, which L15 as restated (ADR-A105, HQ6a1-07) makes Undetermined. Its binding now names a closure, as the examples phase did for the other AIR-3.2 tests, so its expected outcomes stand, and a second assertion checks the open reading: Undetermined, with a Denied value still Denied. This strengthens the test. It is listed here under the non-weakening rule for the maintainer to countersign.
    • test_concept_backends.py pins the set of declared diagnostics. exe:NoClosureLicence joins it.

What to check first: _read_set’s decision and diagnostic expressions in sparql_backend.py, then _closure in eligibility_ir.py, then the module docstring’s statement of the ?closure contract against ADR-A105’s addendum.

Checked while writing the pack. _read_set treats every per-value Undetermined row with exe:MissingCandidate as “no value”. That is sound for both plan kinds. Grouped per value, a present value always counts one candidate, so the diagnostic arises only for a subject with no value. A present interval value that cannot be read reports exe:ValueSpaceMismatch and stays undetermined under a closure.
