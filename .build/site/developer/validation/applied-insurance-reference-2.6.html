Invariant

  • Built:
    • insurance/common’s README §6 “Units and currencies”: ~25 physical units across nine families (acceleration, speed, pressure, length, area, mass per area, power per length, temperature, duration), each qnt:Unit with a skos:exactMatch into QUDT’s http://qudt.org/vocab/unit/ vocabulary and a skos:note naming its SI definition or convention, four qnt:Conversions with their exact factors (knot, mph, g, hPa), and every active ISO 4217 List One currency (about 39) as a qnt:Unit on one money space icm-voc:Money, with its numeric code as skos:notation, its English name as skos:prefLabel, a skos:exactMatch into QUDT’s currency unit vocabulary (http://qudt.org/vocab/unit/CCY_XXX, not the deprecated http://qudt.org/vocab/currency/XXX pattern, confirmed by fetching both a deprecated and a current QUDT page), and a note citing ISO 4217 and the minor unit. common-vocab bumped 0.5.0 → 0.6.0.
    • insurance/peril’s README §5.5 “Intensity measures and thresholds”: a new document vocab/peril-intensity.ttl (its own ontology self-IRI https://www.nebularis.org/neuro-semantic/insurance/peril/intensity, versioned in unison with peril-vocab at 0.5.0, per ADR-A120 addendum decision 3 and the AIR-2.0 precedent set by behaviour-runtime.ttl). Contains prl-voc:IntensityMeasureScheme (a voc:ConceptScheme) and 24 measure concepts, each skos:inScheme/skos:topConceptOf it and prl:measuredOn its own qnt:ValueSpace. Three ordinal measures (ModifiedMercalliIntensity, SaffirSimpsonCategory, EnhancedFujitaRating) each point at a small ordinal scheme of their own (prl-voc:MmiScale I–XII, prl-voc:SaffirSimpsonScale 1–5, prl-voc:EnhancedFujitaScale EF0–EF5), also voc:ConceptSchemes. Seven threshold-defined cause concepts (N.MET.TC.HUR/TST/TDP/TYP/SEV, N.MET.SCS.SLW.DER, N.MET.WIN.BLZ) carry one or two prl:definingThreshold qnt:RangeSets each, built with flat, named blank nodes rather than nested brackets. Thirteen other cause concepts carry prl:intensityMeasure links, and nine carry prl:customaryEventWindow (72 h or 168 h). prl:definingThreshold’s rdfs:comment in spec/peril.ttl gains the sentence “A concept with several defining thresholds meets all of them.”
    • prl:ThresholdDefinitionShape (shapes/constraints.ttl) extended with a second sh:sparql rule: a prl:definingThreshold’s qnt:onSpace must be the prl:measuredOn space of one of the concept’s prl:intensityMeasures (the plan’s AIR26-07). Shapes .version 0.2.0 → 0.3.0. examples/well-formed.ttl gained a placeholder prl:intensityMeasure on N.MET.TC.HUR on the same placeholder space its threshold already used, so the new rule holds on the AIR-2.1/2.2 fixture without depending on peril-intensity.ttl.
    • tools/test_peril_intensity.py (new): AIR26-01 to AIR26-09, 11 tests.

  • Deviations from the plan:
    1. The plan’s “Files” line says vocab/peril-intensity.ttl is “new, carrying the version of peril-vocab.ttl, AIR-2.0” but does not say it needs its own distinct owl:Ontology self-IRI. The first draft reused peril-vocab.ttl’s own ontology IRI verbatim (and its owl:imports named itself), which tools/ontology_releases.py check exposed (both files reporting under the same product name). Fixed to its own self-IRI https://www.nebularis.org/neuro-semantic/insurance/peril/intensity, following the precedent behaviour-runtime.ttl sets for a second spec document in one layer (ADR-A120 decision 2): own self-IRI, version number in unison with the module’s other vocab document.
    2. The 24 measure concepts’ first draft omitted skos:inScheme/skos:topConceptOf on prl-voc:IntensityMeasureScheme, and the scheme itself, and the three ordinal scales, were declared a owl:Class rather than a voc:ConceptScheme. Found while writing AIR26-02 (every measure is read as a scheme member). Fixed: the scheme and the three scales are now voc:ConceptScheme individuals with fnd:hasIdentity/fnd:hasGovernanceState, and every measure concept is skos:inScheme/skos:topConceptOf the measure scheme.
    3. prl:ThresholdDefinitionShape did not, before this slice, check that a prl:definingThreshold is on a space one of the concept’s prl:intensityMeasures actually measures, so AIR26-07 (a deliberate negative case placing HUR’s threshold on the wrong space) found no violation. This is the rule the plan’s own test row describes, so it was missing, not deliberately deferred. Added the second sh:sparql rule described above, bumped shapes .version, and gave examples/well-formed.ttl’s N.MET.TC.HUR a matching placeholder measure so the existing AIR-2.1/2.2 fixture still conforms.
    4. Found a documentation gap while writing the currency list: the five last currencies (COP, VND, PKR, BDT, ISK) were drafted without their skos:exactMatch, caught and fixed before this Handoff, not after.
