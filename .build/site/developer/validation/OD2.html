Validation Pack: OD2, sections 1 to 3 of a README in the layout

Unit: improved-ontology-documentation, slice OD2 (plan). Implements: ADR-A126 decisions 1 (section 3), 10 and 13, and RC1-C5’s section 3 rule. Built autonomously, at the maintainer’s request of 2026-10-18. The decisions taken alone are listed below, for the maintainer to keep or overrule.

Invariant

For a README in the layout, each document its section 2 header table names opens with exactly what sections 1 and 2 state: its prefixes, its ontology header, dct:description from section 1 as plain text, its creators and contributors by IRI and never by name, and the Dublin Core terms it uses declared locally. A README not in the layout extracts exactly as before. A migrated README holds one catalogue entry, in section 3.

What changed

  • tools/literate_grammar.py, new, standard library only. A Turtle writer for terms, blank nodes and lists, with a fixed predicate order. Markdown to plain text with links at the release tag. Section 2’s three tables. compile_layout(), which returns each document’s opening text.
  • tools/literate_extract.py. scan() also records the prose lines and where catalogue blocks open. plan() takes the compiled openings and puts each document’s blocks after them, refusing a block for a document the header table does not name. The version checks now read every output document. main() compiles a README in the layout, and the layout check requires its one catalogue entry in section 3.
  • tools/test_literate_grammar.py, new, with tests OD2-T1 to OD2-T9.
  • tools/test_literate_extract.py. OD1-T11’s README gains a header table and a catalogue entry, which a migrated README now needs, and the test writes instead of checking, since there is no committed file to check against. It tests the same thing as before, a warning on a misnumbered section and an error on a missing one.
  • mise.toml. check:ontology-catalog runs tools/test_literate_grammar.py.
  • docs/architecture/literate-specifications.md. Sections 1 to 3 describe the header table as built, the prefixes added, the order of a document, and the section 3 rule.

Decisions taken alone, for the maintainer

  1. The header table has one row per document, with the columns Document, Ontology IRI, Version IRI and Imports. This replaces the Field and Value table first drafted in the conventions document. A module with several documents (ADR-A120) needs a row each. The version IRI is written in full because it does not always extend the ontology IRI. For example, Eligibility’s ontology IRI is .../neuro-semantic/eligibility and its version IRI .../neuro-semantic/lattice/eligibility/0.12.0.
  2. Section 1 becomes the dct:description of every document the README generates, not only the main spec document, so each document describes itself.
  3. rdf:, rdfs:, owl:, xsd: and dct: are added with their standard namespaces when the prefix table omits them, and a different binding for one of them is refused.
  4. Only the header table is required in section 2. The prefix and contributor tables are optional, so a module can migrate before its contributor table is agreed. The display name column is optional too.
  5. A document’s order is its ontology header, then every other generated statement sorted by subject, then anonymous statements, then the README’s blocks for it in document order. Blocks are verbatim Turtle, which a standard-library extractor cannot sort.
  6. The repository’s blob URL is a constant (https://github.com/nebularis/lattice/blob/), marked as a shortcut, so a downstream README’s links would point at LATTICE. It moves to the catalogue’s conventions when downstream catalogues exist (RC4).
  7. Link targets. The release tag comes from the main spec document’s version IRI, by the versioning policy’s naming rule, and a relative link with no main spec document is refused. A link to an anchor alone resolves to the README at that tag. A link that leaves the repository is refused. An image in section 1 is refused, as tables and headings are.
  8. In a migrated README, every document takes the prefix table’s prefixes. The extractor no longer copies the main spec document’s prefixes into its other documents, as it does for an unmigrated README.

Decisions answered

2026-10-18, by the maintainer: decisions 2, 3, 4, 6, 7 and 8 agreed.

  • Decision 1 agreed. The header table lists ontology documents only, the spec and vocab documents. Shape and projection files have no ontology header, and their targets are in the catalogue entry. The header table’s documents and the entry’s extract.spec and extract.vocab name the same files. Both stay, held equal by RC1-T3 now and by every extraction after RC4 (OD2-Q1, option a).
  • Decision 5 changed (OD2-Q5, option b). A document’s blocks are ordered by their own text, not their place in the README, and a block of a migrated README may not declare a prefix. OD-D18 then holds in full. ADR-A126 decision 10 is clarified in place to say so. Tests OD2-T10 and OD2-T11 were added and pass. A later change is planned so that the versioning check considers only a document’s graph (TD-51).

The maintainer ran every test suite on 2026-10-18, before this change, and all pass.
