Validation Pack: ELC, the composition operation

Unit: improved-ontology-documentation, slice ELC (plan). Implements: OD-D44, OD-D45 and OD-D46, with addenda to ADR-A05 and ADR-A03. Built autonomously, at the maintainer’s request of 2026-10-19. The decisions taken alone are listed below.

Invariant

Only an admission profile declares a composition operation (elg:compositionOperation, AllRequired or AnySufficient). Only a condition that is not a profile declares a match strategy and a wildcard policy. The shapes report each declared in the wrong place. No graph in the repository names elg:CompatibilityOperation, elg:compatibilityOperation, elg:DimensionConsistent or elg:E6, and every example and test graph conforms.

What changed

  • Eligibility’s README, and the files it generates:
    • elg:CompositionOperation and elg:compositionOperation (domain elg:AdmissionProfile) replace the old terms. elg:DimensionConsistent and elg:E6 are gone.
    • elg:AdmissionProfile’s table requires one composition operation and no match strategy or wildcard policy. elg:Condition’s table keeps only elg:negated.
    • Two hand-written shapes in constraints.ttl. elg:SingleConditionMechanismShape requires a match strategy and a wildcard policy of a condition that is not a profile, and elg:CompositionOnProfileShape allows a composition operation only on a profile.
    • L1 to L3 restated. AllRequired and AnySufficient gain definitions. E4 and E5’s comments name the operations.
    • §5.1, §5.2, §5.4, §5.8, §7, §9, §12 and §13 follow, and §5.2 explains conditions and profiles.
  • Every other graph naming the old terms, rewritten by one script and checked graph to graph, file by file: 31 example files in Instrument, Eligibility, Wording, the insurance exposure module and Insure-O, four conformance cases, one gate case, two Eligibility fixtures and MORK’s Executable.ttl (exe:usesCompositionOperation). The same rule was applied to Turtle inside nine Python test modules.
  • Instrument’s product-warranty.ttl. ex:misuse-not-defect composes two conditions but was typed elg:Condition. It is now an elg:AdmissionProfile, which the new shapes required.
  • The compilers. They read elg:compositionOperation and write exe:usesCompositionOperation. A composition operation they cannot evaluate, for example one a downstream ontology adds, is still refused with exe:RefusedOperation, whose comment no longer names DimensionConsistent.
  • The migration check escapes line breaks in a difference, so a changed SPARQL literal is one line of a reconciliation file. Before, a difference in a multi-line literal could not be reconciled.
  • Docs. ADR-A05 and ADR-A03 addenda, the glossary, docs/book.html’s sample, the MORK compilers README and Surface’s MorkEnhancements.md (§9.3 now records the retirement). ADR-A89 and ADR-A90 still say DimensionConsistent is refused, which was true when they were decided, and are left as records.
  • TD-55, the migration check’s whole-file blank node labelling.

Decisions taken alone, for the maintainer

  1. elg:compositionOperation’s domain is elg:AdmissionProfile. It restates what elg:CompositionOnProfileShape checks. A reasoner would infer that a condition carrying it is a profile, so the shape, read without a reasoner, is what reports a misplaced one.
  2. The non-profile rule is a hand-written sh:or (a profile, or one match strategy and one wildcard policy), since the restriction table cannot target “a condition that is not a profile”. Its message sits on the node shape, since the sh:or members are anonymous.
  3. exe:RefusedOperation stays, for an operation a downstream ontology adds. Its test now uses such an operation in place of DimensionConsistent.
  4. AllRequired and AnySufficient gain definitions, the strong Kleene readings ADR-A89 states. Eleven individuals still have none (README §13).
  5. The warranty carve-back is typed a profile, which makes it versioned (fnd:Version), as every profile is. Nothing else in that example changed.
  6. The reconciliations are against 82fc2b25, the commit before ELC. OD6’s command against dab1c790 with OD6’s file no longer passes on this branch, since ELC changed the graphs after it. It passed at a177bda7.

Commands

mise exec -- python -m pytest tools/test_eligibility_examples.py tools/test_closures.py tools/test_literate_migration_check.py tools/test_instrument.py tools/test_parameter_bindings.py tools/test_regimes.py -q
