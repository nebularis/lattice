Validation Pack: FMH-H2.3, the named-graph row writers

Unit: formal-methods-track-h, slice H2.3, planned in plan §4.1 under ADR-A123 and its two addenda of 2026-10-12. One slice beyond the sizing rule, by the maintainer’s approval (H-D21). For countersignature (non-weakening rule): two items, below, countersigned by the maintainer on 2026-10-12. Open decisions: none.

Invariant

The four named-graph operations, create-if-absent, cas-replace, tombstone-delete and unconditional-write, each with its dataset-guard variant where it has one, render the query their templates do (apart from the guard), a request with a missing or mistyped parameter writes nothing, and a caller that names the root’s graph itself cannot write into any graph but the one the naming rule gives.

What changed

  • Seven templates ported in builders.py (create, replace and tombstone with their dataset-guard variants, and the unconditional write), 11 builders in all with H2.2’s. The harness now compares 90 operations, every one equal to its template.
  • The scope rule (H2.3-Q2). UnboundGraphVariable accepts a GRAPH ?g in an inner group when an enclosing group has bound ?g before it. A BIND still sees nothing of the enclosing group. An engine test (T2) shows rdflib returns only ?g’s triples for an OPTIONAL, a nested group and a UNION branch.
  • Param.equals (ADR-A123, second addendum, and the maintainer’s direction of 2026-10-12). A parameter can declare an expression it must equal. ParameterGuard.derive emits sameTerm($p, expr) after the parameter’s type test, check runs every equals through the guard-expression checker (ClockInGuard, UnknownFunction, WrongGuard, UndeclaredParameter apply), and GUARDS_OFF drops it with the type tests. A builder never passes guard conjuncts. A new rule, InvalidEquals, refuses an equals on an optional or slot parameter or one that names a variable (the guard group binds none).
  • The caller-named graph. build(..., graph_names="caller") declares $g with equals the naming rule of ADR-A122 decision 8 and writes GRAPH $g for ?g. persistence instantiate --caller-graph-names selects it, until H2.7 records the choice in the compiled profile. It changes only the operations that name a graph.
  • Roles written down apart from the table. A probe that swapped the metadata and transaction roles in GRAPH_ROLES was not caught, since the existing role test asks the table for the answer. T32 states each graph’s role independently.
  • cas-replace-value-guard is not ported (TD-43, H2.3-Q1). $assertGraph and $retractGraph stay optional (H2.3-Q3). TD-34’s row lists the operations done.

For countersignature

Both countersigned by the maintainer, 2026-10-12.

  1. A refusal case removed from test_ir.py: “GRAPH ?g in an OPTIONAL after an outer BIND of ?g” (UnboundGraphVariable). H2.1 added it, and the planning of H2.3 found it wrong in intent (plan §4.1, fact 1). It is replaced by three refusals that still hold, a GRAPH ?g in an OPTIONAL or a UNION branch that nothing binds, and one bound only after the group that uses it, and by three accepted cases (T1) with the engine test (T2).
  2. A test input changed in test_graph_naming.py (HO8-T1, T2, T2b). They bound $epoch as an xsd:integer, which the README says is a different term and never matches. The create now carries the parameter guard, which refuses it, so the input is xsd:long. The assertions are unchanged.

Review, 2026-10-12

check:persistence ran at 2003 passed, 1 xfailed, as this pack says. The ports, the scope rule, Param.equals and the caller-named form match plan §4.1 and both ADR-A123 addenda. Three points, each now handled:

  1. An unknown graph_names was accepted by the bootstrap and append builders, which ignore the option. build and build_recording now refuse it for every builder, and T28 also checks the append builder.
  2. rdflib writes a template triple whose graph variable is unbound into a new blank-node graph, where SPARQL 1.1 Update skips it (T8, checked again by the review). The guard prevents it, but with --no-parameter-guards a missing $root leaves an orphan graph on rdflib. Recorded as TD-44, with a capability field for H5, and noted in the README’s guards paragraph.
  3. The scope rule probed at its edges by the review. A GRAPH ?g is refused when the outer ?g is bound only in an OPTIONAL or one UNION branch, or only after the inner group, and accepted when it is bound in every solution before it, including by a sibling group. Each matches the join rule.

The two countersignature items above stand for the maintainer.

The golden diff (T29)

fixtures/ir/replace-named-graph.rq and replace-named-graph-caller.rq. The caller-named form differs from the default in nine lines. The sweep and payload blocks and the OPTIONAL sweep read GRAPH $g where they read GRAPH ?g. The BIND(IRI(CONCAT(...)) AS ?g) is gone. The guard line gains ISIRI($g) and sameTerm($g, IRI(CONCAT(...))).
